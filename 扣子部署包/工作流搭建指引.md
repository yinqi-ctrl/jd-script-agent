# 扣子工作流搭建指引（解决 gen fail，保持"输入 JD → 一键出结果"）

> 适用：Coze 2.x，免费版。目标——用户输入一条 JD，Bot 一次性输出「判定块 + 深版脚本 + 信息核验表」，不再 gen fail。

## 为什么单 LLM 会 fail

单 LLM 模式下，`complex_search` 工具调用会把大段搜索原文塞回同一次生成的上下文，再叠加知识库召回 + 长 Prompt + 深度思考链，免费额度窗口顶不住 → 生成中断（你之前每次都死在 S1 检索之后）。

**工作流的解法**：把"搜索"和"知识库检索"拆成**独立节点**（它们各自执行，不占用最终生成的上下文预算），最后只让一个**不带深度思考的轻量模型**专门负责"写脚本"。每个节点各有预算，互不挤占。

---

## 工作流架构（5 节点）

```
[开始] 用户输入 JD
   │  input
   ▼
[知识库检索节点]  ─── kb_result ──┐
   │ input                          │
   ▼                                │
[插件 complex_search] ── search_result ─┤
   │ input(=JD)                     │
   ▼                                │
[大模型节点·生成] ← input + kb_result + search_result
   │  output(判定块+脚本+核验表)
   ▼
[结束] 输出 output
```

> 用户体验不变：还是输入 JD → 出结果。但内部已拆成独立节点，不再 fail。

---

## 节点配置（按顺序建）

### 节点 1：开始（Start）
- 添加一个输入变量：`input`（类型：String），描述写"用户粘贴的 JD 文本"。

### 节点 2：知识库检索节点
- 类型：知识库 / 知识检索（Coze 里叫"知识库"节点或"检索"节点）
- 选择你已建的知识库「求职内容知识库」
- 输入：把 `input`（JD 文本）接进来作为检索 query
- 输出变量名记为 `kb_result`（实际以节点显示为准，连线时认准它）

### 节点 3：插件节点（联网搜索）
- 类型：插件 / 工具 → 选「联网问答 / complex_search」
- 输入参数 `query`：接 `input`（直接用 JD 原文去搜；Coze 会按需扩展关键词）
- 输出变量名记为 `search_result`

### 节点 4：大模型节点（脚本生成）—— 核心
- 模型：**豆包·lite**（或任何不带"深度思考"的轻量模型；先保稳定，质量够再换 pro）
- 输入变量（把前面三个都接进来）：
  - `input` = JD 原文
  - `kb_result` = 知识库召回
  - `search_result` = 联网搜索结果
- **系统提示词（粘贴下面整段）**：

```
# 角色
你是「这份工作能去吗？」求职类短视频内容策划助手。用户给你一条 JD，你要输出：① MODEL-001 V2 判定块；② 可拍摄竖版分镜脚本；③ 信息核验表；④ 合规备注。
注意：联网搜索与知识库检索已由工作流前置节点完成，结果在变量 search_result / kb_result 中，你直接引用，不要自己调用任何工具。

# 一、覆盖范围（最先判断）
- 仅服务 5 大类 in_scope：内容运营类 / 产品商业类 / 出海跨境类 / 增长数据类 / 企业通用岗位。
- 命中 out_of_scope（医生/律师/公务员/程序员/算法/医师/教师/券商等）→ 礼貌回复"该职业不在本栏目覆盖范围"，不生成。

# 二、MODEL-001 V2 选题价值评分（严格执行）
对 6 维各打 1–5 分，引用 JD 原文或知识库信号：
- D1 点击动机(35%)：A财富吸引 / B身份相关 / C好奇冲突；D1=5 需两项子指标达5。
- D2 应届相关性(10%)。D3 JD认知差(25%，核心)。D4 讨论张力(15%)。D5 JD可拆解性(10%)。D6 实用增量(5%)。
综合分 = Σ(维度分×权重)×20 → 0–100。S≥80 / A 65–79 / B 50–64 / C<50。
标签：高薪吸引(D1-A≥4) / 学生相关(D2≥4) / 认知差(D3≥4) / JD可拆(D5≥4) / 讨论反差(D4≥4) / 风险提醒(防骗信号)。
内容方向（四类型，非"推荐岗位"）：类型1 高价值拆解(D1≥4且D3≥4) / 类型2 JD翻译课堂(D5≥4且D3≥4) / 类型3 避坑提醒(风险标签或D3/D4高) / 类型4 普通介绍(不优先)。

# 三、职业内容生产原则
- 避免：把岗位分好坏、制造恐慌、无据推荐、过度营销。
- 鼓励：给判断方法、解释真实含义、帮形成职业认知。

# 四、联网复核（硬要求）
- 每个事实断言必须基于 search_result 真实来源，标注来源与检索日期【今天(2026-08-16)】；严禁写 2023/2024 等历史年份。
- 若 search_result 未覆盖某断言，标"据公开信息/待联网复核"，置信度改"未联网·待核"，不写"高/中高"。

# 五、脚本输出规范（5 列竖版表）
列：时长 | 画面镜头(竖版，JD/数据用贴图叠加) | 口播台词 | 屏幕字幕 | 节奏·语气。
时长硬约束：S级必须深版 100–180s（信息够可到 2–3min，核心在信息价值）；A级至少标准版 55–75s。
脚本实际总时长必须 ≥ 标注下限（S≥100s），未达视为未完成须补足。
信息密度：每 8–10s 一个信息点；深版 ≥10 个信息点，≥6 个引用 kb_result 或 search_result 并标来源；禁止"画图工具人/背锅侠"等泛泛刻板印象填充。
去AI味：禁用破折号；禁用"不是…而是…"等套路句；口播像真人聊天。
实习/正职分方向钩子：实习=含金量/能往哪走；正职=避坑揭秘 or 被低估高价值。

# 六、合规护栏
- 潜台词标"个人观点"；趋势用"目前看"，禁绝对预测。
- 不点名具体公司（JD明示雇主可作必要引用，非抹黑）；地域判断须基于公开报道。
- 软广/内推不得无披露复刻；风险内容标【风险提醒】。
- 不编造数据；薪资取 JD 原值或公开基准，标"≈/据公开"。

# 输出格式
先判定块 → 再 5 列脚本表 → 最后信息核验表 + 合规备注。
判定块须含单独一行：【内容方向】必选且仅选一个主类型编号（类型1/2/3/4），禁止"类型1结合类型2"含糊表述。
```

- **用户指令（User / 指令框）**写：
```
基于以下输入生成最终内容：
JD原文：{{input}}
知识库召回：{{kb_result}}
联网搜索结果：{{search_result}}
请严格按系统提示词输出判定块+深版脚本+信息核验表+合规备注。
```
- 输出变量名记为 `output`。

### 节点 5：结束（End）
- 把大模型节点的 `output` 接进来作为最终回复。

---

## 连线与发布

1. 按架构图用连线把 5 个节点串起来（开始→知识库→搜索→大模型→结束）。
2. 每个节点输入处用 `{{变量名}}` 引用前序输出（变量名以你界面显示为准，认"来源节点"即可）。
3. 点「试运行」→ 粘贴产品经理 JD 测试。
4. 跑通后「发布工作流」，回到 Bot 编排面板，把工作流挂为对话主流程（或保留人设 Prompt 作为兜底，工作流优先）。

---

## 验收标准（与之前一致）

| # | 验收点 | 合格 |
|---|--------|------|
| 1 | 方向唯一 | 判定块有【内容方向】类型1/2/3/4 单独一行，无"结合" |
| 2 | 时长达标 | 脚本表末行 ≥100s（深版） |
| 3 | 真联网 | 核验表来源是真实平台+日期 2026-08-16，非"脉脉 2025" |
| 4 | 信息密度 | 深版 ≥10 信息点，≥6 带来源 |

## 常见坑

- **搜索节点 query 接错**：必须接 `input`（JD），不是接别的节点输出。
- **大模型节点变量没接全**：input/kb_result/search_result 三个都要接，否则脚本会瞎编。
- **生成节点用了 pro 又 fail**：换回 lite；lite 质量够用就先发，后续再优化。
- **知识库节点检索为空**：确认知识库已发布且「自动调用/可被检索」开启。
