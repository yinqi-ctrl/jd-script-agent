# 扣子（Coze）部署就绪包 · 使用说明

> 本文件夹是《这份工作能去吗？》智能体的**部署就绪资产**。知识库主体已按 V2 评分模型（MODEL-001 V2）完成重构，下面是从本地知识库到扣子 Bot 的落地步骤。

## 一、目录内容
- `知识库纯文本/`：事实类条目已转纯文本，可直接上传扣子知识库。
  - 数量：JD 21 / EXP 21 / IND 17 / CASE 8，共 **67 条**。
  - 格式：已删除 YAML frontmatter；每个文件首行写为 `# 类型:in_scope 类别:xxx 角色:xxx`，便于大模型按范围筛选、避免 out_of_scope 误用。
  - 重跑：若本地知识库有更新，执行 `convert_kb.py` 重新生成即可（不覆盖原库）。
- `convert_kb.py`：转换脚本（剥离 frontmatter + 写首行范围标签）。

## 二、在 coze.cn 落地步骤
1. **新建 Bot**：名称「这份工作能去吗？」，简介填「拆解真实 JD，帮大学生看懂岗位真实情况」。
2. **建知识库**：
   - 方案 A（推荐）：建 **1 个**知识库「求职内容知识库」，上传 `知识库纯文本/` 下全部 .md（每个文件=一条，分段边界清晰）。
   - 方案 B：建 2 个——`岗位与趋势库`（JD+EXP+IND）、`爆款案例库`（CASE）。
3. **粘人设 Prompt**：把 `知识库/00_扣子Coze部署方案与知识库梳理.md` 的 **第三~八节**（角色 / 覆盖范围 / 工作流程 / MODEL-001 V2 评分 / 生产原则 / 联网复核 / 脚本规范 / 合规护栏 / 输出格式）整体粘进「人设与回复逻辑」。该 Prompt 已是 V2（六维+标签+四类型，无 R1–R10）。
4. **加插件**：添加「联网搜索」，用于工作流"未命中 in_scope 条目"分支补全。
5. **搭工作流**（可选但推荐）：按同文档「第四部分 节点图」搭：范围判定→拒答选择器→知识库检索→未命中联网→评分节点→案例检索→生成节点→结束。
6. **发布**：调试几条 JD（正职避坑 / 高价值 / 实习发展探索 / 风险提醒）后发布。

## 三、关键边界（务必保留）
- **规则类（⑤脚本模板 + ⑥评分模型）绝不进知识库 RAG**，已完整写进 Prompt，保证严格遵循。
- **覆盖范围**只服务 5 大类 in_scope（内容运营/产品商业/出海跨境/增长数据/企业通用），out_of_scope 礼貌拒答。
- **风险内容**走类型3 就业避坑提醒，带【风险提醒】但不用绝对批判口吻。
- **所有事实断言先联网复核**并附信息核验表。
