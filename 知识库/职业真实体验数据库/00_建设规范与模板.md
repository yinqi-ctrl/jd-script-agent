# 职业真实体验数据库 · 建设规范与模板

> 模块定位：模块②。帮助智能体理解岗位**真实工作状态**，避免脚本只照 JD 描述职业、缺少"人味"与真实感。
> 与模块①（JD库·官方要求）、模块④（案例库·爆款结构）互补：JD 讲"招聘方想让你看到的"，本库讲"从业者真正在过的日子"。

---

## 一、本库要解决的核心问题
- JD 库是"岗位说明书视角"，偏官方、理想化；真实体验库补齐**从业者视角**的真实感。
- 智能体生成脚本时，应优先从本库召回"真实工作状态 / 认知差 / 从业者吐槽"，让口播有细节、有共鸣、有反差。
- 检索逻辑（智能体工作流）：拿到 JD → 先在本库按 `profession`/`tags` 检索 → **命中则引用真实体验**；**未命中则触发联网检索**（公开论坛/报道综合），回填本库。

## 二、信息字段（YAML frontmatter + Markdown 正文，沿用全库规范）
| 字段 | 说明 |
|------|------|
| `exp_id` | 唯一编号，格式 `EXP-XXX` |
| `profession` | 岗位名称（与 JD 库 `position` 对齐，便于关联） |
| `industry` | 所属行业 |
| `related_kb` | 关联模块① JD 的 `jd_id`（双向关联） |
| `popularity` | 热门度：高 / 中 / 上升（用于选题热度参考） |
| `data_quality` | 数据性质：`A-联网综合`（公开讨论综合，非单人访谈） |
| `source` | 数据来源（知乎/小红书/百度健康/证券报道/公开调研等） |
| `tags` | 检索标签（含"认知差大/一人多岗/高门槛/稳定"等） |
| `video_value` | 适合内容类型：避坑 / 揭秘 / 对比（列表） |
| `retrieval_summary` | 一句话摘要，供智能体快速召回判断 |

## 三、推荐数据来源
- **从业者社区**：知乎（职业话题高赞回答）、小红书（打工真实分享）、脉脉（职场吐槽）。
- **行业垂直**：丁香人才/百度健康（医护）、券商中国/财新（金融）、人人都是产品经理（PM）。
- **公开调研/报道**：清华/人大就业报告、券商薪酬报道、媒体职业观察稿。
- **朕合原则**：单条体验须综合≥3 个独立信源提炼共性，不采信单一极端个案；个体有差异，须标注"仅供参考"。

## 四、数据整理规范
1. 单职业一文件，命名 `entries/EXP-XXX_岗位名.md`。
2. **真实感优先**：多写具体细节（典型一天时间线、常用工具、真实吐槽原话感），少写空泛形容词。
3. **认知差结构**：必须填写"大众以为 vs 实际情况"对照，这是本库对脚本最有价值的资产。
4. **合规红线**：
   - 不点名具体公司/机构（用"某大厂/某券商/基层单位"）；
   - 个体经历≠群体结论，正文须标注"综合公开讨论，个体差异大，仅供参考"；
   - 引用到脚本时须带"个人观点/供参考"声明（同模块④口径）。
5. `data_quality` 统一标 `A-联网综合`，区别于 JD 库的"建模样本"。
