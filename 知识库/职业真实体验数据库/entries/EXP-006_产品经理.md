# 职业基本信息
- **职业是什么**：定义产品该做什么、为什么做、怎么做的人；输出 PRD、原型、路线图，串联研发/设计/运营/老板。
- **大众印象**：高大上、动动嘴画原型、指挥别人干、离老板近、薪资不错。
- **实际工作定位**：需求与责任的"连接器+兜底者"；核心价值是"在约束里做对的取舍"，但常因职责边界模糊成为最终背锅位。

# 真实工作状态
- **日常工作内容**：需求调研、写 PRD、画原型、评审、跟研发对齐、看数据复盘、向老板汇报、处理各方撕扯。
- **典型一天**：
  - 10:00 站会，确认研发阻塞；
  - 11:00-12:00 写/改 PRD，被研发挑战可行性；
  - 14:00-17:00 拉通设计、运营、研发对齐，会议不断；
  - 19:00 后 安静写文档（白天没时间），回老板消息；
  - 上线出事，第一个被问"需求是谁定的"。
- **高频任务**：写需求、开会对齐、看数据、处理变更、向上汇报。
- **常用工具**：Axure/Figma/墨刀、Jira/Confluence、飞书/钉钉、脑图、SQL/数据看板（进阶）。
- **工作压力来源**：需求反复变、上线延期背锅、跨部门推诿、老板拍脑袋、指标（DAU/营收）压力。

# 从业者反馈
- **常见优点**：离业务近、成长综合、转管理/创业顺、话语权相对高。
- **常见缺点**：责任大权力小、会议多、边界模糊背锅多、易被研发"视而不见"。
- **行业吐槽**："上接领导下接研发，中间自己扛锅""一切问题，产品经理背锅""白天开会，晚上写文档才是真"。
- **新人容易踩坑的地方**：
  1. 以为会画原型就够了，不懂业务和技术可行性；
  2. 不会拒绝需求，需求池越堆越乱；
  3. 沟通弱，被研发/老板双向挤压；
  4. 不做数据复盘，决策全靠拍脑袋。

# 职业认知差
- **大众以为**：产品经理=动嘴指手画脚、轻松高大上、离钱近。
- **实际情况**：它是"背锅侠+连接器"——权力小于责任，大量时间花在跨部门的撕扯与对齐上；真正值钱的是业务判断和取舍能力，而非画图；新人若只学工具不学业务，极易沦为"文档打字员"。
