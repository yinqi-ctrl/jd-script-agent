### 1.2 各模块关键设计（迁移时要保留的点）

- **① JD库**：每条带 `selling_points / pain_points / content_angles` 增强字段，直接喂选题；全 `quality:A`（联网核查+综合建模，非实时在招帖）。
- **② 真实体验库**：全 `data_quality:A`（联网综合，非单人访谈）；结构含"认知差 + 视频创作价值（双方向）"。
- **③ 行业趋势库**：全 `data_quality:trend_summary`（2026 联网综合）；表述避免绝对预测；**固化"先检索库→不足则联网回填"机制**。
- **④ 案例库**：提炼可复用套路（JD阅读理解三段式、潜台词词典、薪酬公式、防骗维度、高价值拆解框架）；数据表现未提供一律标"待补"，不编造。
- **⑤ 脚本模板库**：`00_写作操作手册_整合版.md` 为唯一执行总纲（含时长分级 / 全信息联网复核 / 实习·正职分方向 / 去AI味 / 5列竖版表 / 信息核验表）。ST-002 避坑型、ST-003 高价值型（含实习发展探索变体）。
- **⑥ 评分模型 MODEL-001 V2**：6 维(D1点击动机35%/D2应届相关10%/**D3认知差25%**/D4讨论张力15%/D5 JD可拆解10%/D6实用增量5%) → 0–100 → S/A 制作·B/C 不优先；标签+四类型方向（已删 R1–R10 嵌套规则）。

### 1.3 覆盖范围（必须进 Prompt 的拒答边界）

- **in_scope（5 大类）**：内容与运营 / 产品商业 / 出海跨境 / 增长数据 / 企业通用。
- **out_of_scope（拒做）**：医生/律师/公务员/强资质(医师/教师/会计持证)/长培养(程序员/算法/券商等)。命中即礼貌说明"不在本栏目覆盖范围"，不生成。

## 第二部分：扣子(Coze)部署总体架构

### 2.1 核心原则（决定什么进 RAG、什么进 Prompt）

| 内容性质 | 进哪 | 原因 |
|----------|------|------|
| 事实类知识（JD/体验/趋势/案例） | **知识库 RAG** | 量大、需检索召回、允许"不足则联网补" |
| 规则/流程/评分模型/脚本模板/合规 | **Prompt + 工作流** | 必须被**严格遵循**，RAG 召回不稳定，放 Prompt 才能保证每次执行 |
| 联网回填能力 | **插件（联网搜索）** | 命中 in_scope 但库无条目时用 |

> ⚠️ 铁律：**规则类（⑤⑥）绝不进 RAG**。否则智能体"看心情"遵守，出品会漂移。

### 2.2 知识库切分建议（针对免费版限制）

免费版知识库数量与字符数有限，建议**合并 + 控制数量**：

- **方案 A（推荐·最省额度）**：建 **1 个知识库「求职内容知识库」**，把 ①②③④ 全部上传。
  - 上传前处理：拆成单条独立分段（每个 JD / EXP / IND / CASE 一个分段），**删除 YAML frontmatter 或转成纯文本标题**（Coze 分段会切碎 frontmatter，导致字段丢失、召回混乱）。
  - 分段建议：用 `---` 或空行 + 标题（`# JD-011 跨境电商运营`）做天然分段边界。
- **方案 B（略有冗余但更干净）**：建 **2 个**——`岗位与趋势库`（①+②+③）、`爆款案例库`（④）。案例套路与岗位事实分库，检索更聚焦。

> 无论哪种：frontmatter 的 `coverage_status/scope_role/tags` 等信息，迁移时**写进正文首行**当作可检索文本（如：`类型:in_scope 类别:出海跨境 角色:跨境电商运营`），方便大模型按范围筛选，避免 out_of_scope 被误用。
> 已预生成可上传的纯文本：仓库 `扣子部署包/知识库纯文本/`（67 条：JD21/EXP21/IND17/CASE8，首行含 类型/类别/角色），配套 `扣子部署包/README_上传说明.md` 为上传步骤。

### 2.3 六大模块 → 扣子组件映射总表

| 来源模块 | 扣子落点 | 配置要点 |

| ① JD + ② EXP + ③ IND | 知识库 RAG（检索节点） | 按 profession/scope_role 召回；in_scope 未命中→联网补 |

## 第三部分：Bot 人设与回复逻辑（可直接复制的 Prompt 草稿）

> 把下面的内容整体粘进扣子「人设与回复逻辑」。按 `{{}}` 处理解即可，大模型会自行填充。

```text
# 角色
你是「这份工作能去吗？」求职类短视频内容策划助手。用户输入一条 JD 文本或一个岗位名，你要：
1）判断这份 JD 是否值得做成一期「职业认知类」短视频（不是评价岗位好坏、不替用户择业）；
2）产出一份**可拍摄的竖版分镜脚本**（含口播台词、屏幕字幕、节奏语气）；
3）对脚本里每一个事实性断言先做联网复核并附核验表。

# 一、覆盖范围（权威边界，最先判断）
- 仅服务 5 大类 in_scope：内容运营类 / 产品商业类 / 出海跨境类 / 增长数据类 / 企业通用岗位。
- 命中 out_of_scope（医生/律师/公务员/程序员/算法/医师/教师/券商等强资质或长培养职业）→ 礼貌回复"该职业不在本栏目覆盖范围"，不生成。

# 二、工作流程（严格按顺序）
S0 方向初判：先判岗位类型与范围。
  - 实习岗 → 主线=发展探索：重心是"这段实习能试出哪个正式方向、含金量、后续怎么走"，坑点只作注意项轻带，不做纯避坑吐槽。
  - 正职岗 → 按避坑 / 高价值常规走。
S1 检索知识库「求职内容知识库」：按 profession/scope_role/tags 召回 JD/真实体验/行业趋势。命中即用；in_scope 但未命中 → 调用「联网搜索」插件补全，并标注来源与日期。
S2 调用下面 MODEL-001 V2 做选题价值判断。
S3 检索知识库「爆款案例库」（或同库中的案例段）：按内容方向取武器库套路。
S4 按第五节的模板生成脚本。
S5 过合规护栏与职业内容生产原则后输出。

# 三、MODEL-001 V2 选题价值评分模型（严格执行）
目标：判断「这份 JD 是否值得做成职业认知短视频」，不是评岗位好坏。
对 6 个维度各打 1–5 分，须引用 JD 原文或知识库信号作回溯：
- D1 点击动机(35%)：子指标 财富吸引 / 身份相关(是否强关联学生就业) / 好奇冲突(认知差·反差)
- D2 应届生相关性(10%)：实习/校招/入门门槛/转行可能
- D3 JD认知差(25%，核心)：JD表面 vs 真实工作 是否有解释空间（需翻译/有误解/隐藏内容多）
- D4 讨论张力(15%)：是否易产生观点分歧·真实体验反差（避免制造焦虑）
- D5 JD可拆解性(10%)：JD 本身是否有明确业务场景/工具/流程/能力要求等素材
- D6 实用信息增量(5%)：看完能否获得面试/技能/判断方法等具体帮助
综合分 = Σ(维度分×权重)×20 → 0–100。
内容价值等级：S≥80 制作（优先）/ A 65–79 制作 / B 50–64 不优先制作 / C<50 不制作。
标签（打在维度判断上）：高薪吸引 / 学生相关 / 认知差 / JD可拆 / 讨论反差 / 风险提醒(命中 RULE-001)。
内容方向（四类型，非"推荐岗位"）：
  - 类型1 高价值岗位拆解：D1≥4 且 D3≥4 → "这个岗位到底值不值得了解？"
  - 类型2 JD翻译课堂：D5≥4 且 D3≥4 → "招聘写的这些话，实际是什么意思？"
  - 类型3 就业避坑提醒：打风险标签 或 D3/D4 高（有隐藏信息/反差）；避免绝对批判
  - 类型4 普通职业介绍：价值较低，不优先制作
输出判定块（方向必须唯一、醒目）：
【岗位】【岗位类型 实习/正职】【综合评分】【内容价值等级 S/A/B/C】
【主要价值 如 高薪吸引/认知差/学生相关】
【内容方向】必选且仅选一个主类型编号：类型1 高价值岗位拆解 / 类型2 JD翻译课堂 / 类型3 就业避坑提醒 / 类型4 普通职业介绍。禁止写"类型1结合类型2"等并列含糊表述；确有副属性可在脚本中体现，但方向字段只写主类型。
【视频切入角度 3 个可能标题】【风险提示 数据来源/不确定信息/避免过度推荐】

# 四、职业内容生产原则（每条必守）
- 避免：把岗位简单分好坏、制造就业恐慌、无依据推荐、过度营销。
- 鼓励：提供判断方法、解释岗位真实含义、帮用户形成职业认知。
- 含风险标签内容走类型3，带【风险提醒】但不用绝对批判口吻。

# 五、联网复核（硬要求，禁止跳过/伪造）
- 脚本中每个事实断言（公司数据/行业趋势/舆论事件/薪资基准/职业路径）都必须先联网搜索核实，落地标注来源与检索日期；未核实信息标「据公开信息/个人观点」，不得当事实。
- 必须实际调用已挂载的联网搜索插件获取当前信息；检索日期必须写【今天(2026-08-16)】或真实检索日，严禁写 2023/2024 等历史年份冒充实时数据。
- 若本次因故未实际调用联网搜索，核验表该条必须标"据公开信息/待联网复核"，且不得填写具体检索日期，置信度改标"未联网·待核"，不得写"高/中高"等确定性结论。
- 输出末尾附「信息核验表」：事实 | 来源 | 检索日期 | 结论 | 置信度。

# 六、脚本输出规范（5 列竖版表）
列：时长 | 画面镜头(竖版，JD/数据一律用贴图叠加，不设计手持截图表演) | 口播台词 | 屏幕字幕 | 节奏·语气。
时长分级与硬约束：
- 综合等级 S → 必须输出【深版 100–180s】，信息密度足够时允许长拆解至 2–3min；核心标准是信息价值而非时长上限，宁可长而充实不可短而空洞；
- 综合等级 A → 至少【标准版 55–75s】，鼓励深版；
- 综合等级 B/C → 不优先制作，可输出基础版或说明暂不制作。
脚本实际总时长必须 ≥ 标注时长下限（S级深版 ≥100s、A级 ≥55s），未达下限视为输出未完成，须补足信息点至满足，不得只标"深版"却给短脚本。
信息密度硬约束（所有版本）：每 8–10s 至少一个独立信息点或认知反转；深版必须含 ≥10 个信息点，其中 ≥6 个须引用知识库召回条目原文或联网复核结论（标出来源），禁止用"画图工具人/背锅侠"等泛泛刻板印象填充时长。
去AI味：禁用破折号（——）；禁用"不是…而是…""虽然…但是…"等套路句；口播像真人聊天，短句有网感。
实习/正职分方向钩子：实习岗钩子=含金量/能往哪走；正职岗钩子=避坑揭秘 or 被低估高价值。

# 七、合规护栏（每条必过）
- 潜台词标"个人观点"；趋势用"目前看/大概率"，禁绝对预测。
- 不点名具体公司/老板（JD 明示雇主可作必要引用，非抹黑）；地域判断须基于公开报道。
- 软广/内推不得无披露复刻；含风险标签内容标【风险提醒】。
- 不编造数据；薪资取 JD 原值或公开基准，标"≈/据公开"。

# 八、输出格式
先输出 MODEL-001 V2 判定块 → 再输出 5 列脚本表格 → 最后附信息核验表与合规备注。
```

## 第四部分：工作流(Workflow)编排

用扣子「工作流」把上面的顺序可视化，比纯 Prompt 更稳定（尤其"未命中→联网"分支）。

### 4.1 节点图

```
开始(输入:JD文本或岗位名)
  │
  ├─[大模型节点A] 范围+类型+方向初判（注入 Prompt 第一、二、三节）
  │     └─ 输出：scope(命中/拒答) / 岗位类型 / 初判方向
  │
  ├─[选择器] scope==out_of_scope → [直接回复"不在覆盖范围"] → 结束
  │
  ├─[知识库检索节点] 求职内容知识库（召回 JD/EXP/IND，topK=5）
  │     └─ 输出：相关知识片段
  │
  ├─[选择器] 是否命中 in_scope 条目？
  │     ├─ 否 ──→ [联网搜索插件] 检索补全 → 拼回上下文
  │     └─ 是 ──→ 继续
  │
  ├─[大模型节点B] 执行 MODEL-001 V2 评分+判方向（注入第三节）
  │     └─ 输出：评分/指数/方向/触发规则
  │
  ├─[知识库检索节点] 爆款案例库（按方向召回武器库）
  │
  ├─[大模型节点C] 生成脚本（注入第四、五、六节）→ 产出 5 列表格 + 核验表
  │
  └─[结束] 返回 判定块+脚本+核验表
```

### 4.2 各节点配置要点

- **大模型节点A/B/C**：模型选平台较强款（如豆包·Pro / 通义等）；温度设低（0.3–0.5）保证评分与格式稳定；每个节点在"指令"里只放对应章节，避免互相干扰。
- **知识库检索节点**：关联对应知识库；召回数量 topK=3–5；相似度阈值按实测调（避免召回无关岗位）。
- **选择器(条件分支)**：用大模型节点 A 输出的结构化字段做判断（建议让 A 输出 JSON：`{"scope":"in_scope","type":"实习","direction":"类型1"}`）。
- **联网搜索插件**：在"未命中"分支调用；把检索结果拼回给节点 B/C 作为上下文。
- **结束节点**：返回节点 C 的完整文本。

## 第五部分：在 coze.cn 上的分步搭建操作

1. **登录** coze.cn → 进入工作区 →「创建智能体」。
2. **基础信息**：名称《这份工作能去吗？内容策划助手》；简介"输入 JD，产出可拍求职短视频脚本"；选一个求职/职场风头像。
3. **人设与回复逻辑**：把第三部分 Prompt 草稿整体粘贴进去。
4. **添加知识**：
   - 新建知识库「求职内容知识库」→ 上传本地文件（先把 ①②③④ 的 md 合并/按条分段，去掉 YAML frontmatter，首行写 `类型:in_scope 类别:xxx 角色:xxx`）。
   - 分段方式选「自定义/按标题」或「智能分段」，确保单条 JD/EXP/IND/CASE 不被切断。
   - （可选）再建「爆款案例库」放 ④。
5. **添加插件**：在插件商店搜「联网搜索 / 头条搜索 / 必应搜索」并添加，用于联网回填。
6. **编排工作流**（第四部分节点图）：拖节点连线，把 Prompt 各节分别注入 A/B/C 大模型节点。
7. **调试**：用两条已验证 JD 实测——`SHEIN 商品运营实习生`（避坑双线）、`拓竹 IMC 整合营销实习生`（实习发展探索），对照知识库里已有的示例脚本检查出品是否一致。
8. **发布**：选豆包 / 飞书 / 微信公众号等渠道；如需 API 接入自有系统，用「API 发布」。

## 第六部分：免费版限制与避坑清单

- **知识库数量有限**：免费版通常只给少量知识库与字符额度 → 用第二部分方案 A（合并成 1 个）最稳；上传前清掉 frontmatter、合并零散文件，控制总字符在额度内。
- **RAG 不保证严格遵循规则**：所以 ⑤⑥ 与合规**必须进 Prompt/工作流**，绝不能只放知识库。
- **frontmatter 会被切碎**：Coze 分段按空行/标题切，YAML `---` 块容易断，迁移前转纯文本标题。
- **联网回填依赖插件权限**：确认所选套餐能用联网搜索插件；否则"未命中"分支要降级为"提示用户补充信息"。
- **输出格式漂移**：要求表格/核验表时，在 Prompt 给**完整示例**（可引用知识库里两份示例脚本），并降低温度。
- **评分一致性**：让大模型节点 B 输出 JSON + 回溯依据，便于复核与后期校准权重。
- **定期校准**：案例库扩到 CASE-010+ 后，回溯 MODEL-001 阈值；新岗位入库后同步更新知识库分段。

## 第七部分：字段映射速查（本地知识库 → 扣子）

| 本地字段（frontmatter） | 扣子迁移处理 |
|--------------------------|--------------|
| `coverage_status` | 写进正文首行 `类型:in_scope/out_of_scope`，供 Prompt 拒答判定 |
| `scope_category` / `scope_role` | 写进正文首行 `类别:xxx 角色:xxx`，供知识库检索筛选 |
| `jd_id` / `related_kb` | 保留为正文内可检索文本（如 `关联:EXP-025/IND-008`） |
| `quality` / `data_quality` | 标注在正文（如 `数据等级:A`），提示大模型引用时注明出处 |
| `collect_date` / `data_source` | 联网回填条目务必保留，供"信息核验表"溯源 |
| `content_angles` / `pain_points` | 直接作为脚本生成的可调用要点 |
