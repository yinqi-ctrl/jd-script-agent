# 行业趋势与职业发展数据库 · 建设规范与模板（V1）

> 模块③：辅助智能体判断「岗位未来发展情况」。与模块①（JD 现状）、模块②（真实体感）互补，形成「现状—体感—趋势」三层信息。

## 一、定位与工作流位置

智能体拿到一条 JD 后的检索顺序：

1. **模块① JD库** → 岗位现状（职责/薪资/门槛）
2. **模块② 真实体验库** → 从业者真实体感（认知差）
3. **模块③ 本库** → 行业趋势 / 职业发展前景（未来）
4. **模块⑥ 价值判断规则库** → 是否值得做一期
5. **模块⑤ 脚本模板库** → 出 ST-002（避坑）/ ST-003（高价值）脚本

**检索机制（关键）**：智能体**先检索本库**获取行业趋势基础；若命中 in_scope 但本库无对应条目（信息不足），则**触发联网检索**回填本库（与模块②逻辑一致）。`out_of_scope` 条目不参与生成。

## 二、条目字段（YAML frontmatter + 正文）

### Frontmatter
| 字段 | 含义 | 取值 |
|------|------|------|
| `coverage_status` | 覆盖状态 | `in_scope` / `out_of_scope` |
| `scope_category` | 五大类之一 | 内容运营/产品商业/出海跨境/增长数据/企业通用 |
| `scope_role` | 岗位角色 | 如「内容运营」「跨境电商运营」 |
| `ind_id` | 条目编号 | IND-001 … |
| `profession` | 岗位名称 | 与 JD 库 `title` 对齐 |
| `aliases` | 别名 | 数组 |
| `industry` | 所属行业 | 如「新媒体/MCN」「跨境电商」 |
| `related_jd` | 关联 JD | `[JD-xxx]` |
| `related_exp` | 关联真实体验 | `[EXP-xxx]` |
| `related_case` | 关联案例（可选） | `[CASE-xxx]` |
| `data_source` | 数据来源概述 | 联网检索来源类型 |
| `collect_date` | 采集日期 | YYYY-MM-DD |
| `data_quality` | 数据完整度 | `A`=联网综合 / `C`=骨架待补 |
| `trend_summary` | 一句话趋势判断 | 避免绝对预测 |

## 三、数据来源与合规

- **联网检索**：职友集/猎聘/BOSS 行业薪酬与岗位趋势页、艾瑞/QuestMobile/巨量算数/易观行业报告、行业媒体（亿恩网/亿邦动力/36氪/晚点）、知乎/脉脉从业者讨论。
- **避免绝对预测**：所有趋势用「目前看 / 大概率 / 存在 X 风险 / 短期承压」等表述，禁止写「一定 / 必然 /  Guaranteed」。
- **基于公开信息总结**，注明来源类型；不编造未公开数据。AI 生成内容标注「趋势基于公开信息综合，非投资建议」。
- **合规红线（沿用全局）**：不点名具体公司造谣；地域/行业判断须基于公开报道，不得绝对化；涉及「潜台词」须标「个人观点」。

## 五、与智能体检索的对接

- 智能体拿到 JD 后，先用 `profession` / `scope_role` / `tags` 在本库检索；命中即引用。
- 命中 in_scope 但无对应 IND → 触发联网检索，按本结构回填新 IND 条目（frontmatter 标 `data_quality: C` 待人工润色或 `A` 联网综合）。
- `out_of_scope` 角色（医生/律师/公务员/程序员等）本库不建条目，不进入生成。
