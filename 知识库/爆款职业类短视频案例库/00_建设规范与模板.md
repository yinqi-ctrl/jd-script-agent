# 爆款职业类短视频案例库 · 建设规范与模板

> 模块定位：《这份工作能去吗？》职业探索类短视频内容策划智能体的**第④个核心知识库**。
> 作用：让智能体学习新媒体传播规律、选题角度与内容结构，从已验证的爆款案例中抽象出**可复用的内容套路**，直接服务于模块⑤（脚本模板库）与下游脚本生成。
> 本库与「岗位JD数据库（模块①）」「职业价值判断规则库（模块⑥）」强关联：案例多是对 JD 的"阅读理解/避坑拆解"，应双向 `related_kb` 关联。

---

## 一、本库需要包含的信息字段（6 组，机器→人双结构）

采用 **YAML frontmatter（机器易解析）+ Markdown 正文（人易读）** 双结构，单条案例一文件。

### A. 案例标识（必填）
| 字段 | 说明 | 取值建议 |
|------|------|---------|
| `case_id` | 案例唯一编号 | `CASE-001` 起，跨模板类型连续编号 |
| `title` | 视频标题/核心口播首句 | 取视频原标题或开场金句 |
| `platform` | 发布平台 | 小红书 / 抖音 / 视频号 / B站 / 快手 |
| `creator` | 账号名 | 学习用途，注明出处；匿名化时标"匿名" |
| `url` | 原始链接 | 留空或标注"失效/需授权" |
| `collected_date` | 采集日期 | `YYYY-MM-DD` |
| `template_type` | 内容模板类型 | 见下方受控词表 |
| `data_quality` | 数据完整度 | `A`=含口播稿/`B`=仅标题或截图/`C`=骨架待补 |

### B. 数据表现（选填，缺则标"待补"）
| 字段 | 说明 |
|------|------|
| `duration_sec` | 时长（秒），未知填 `null` |
| `metrics.likes / collects / comments / shares` | 点赞/收藏/评论/转发 |
| `metrics.heat_level` | 爆款等级：`S / A / B / C / 待补` |

### C. 选题与定位
| 字段 | 说明 |
|------|------|
| `job_role` | 视频主角岗位 |
| `industry` | 行业 |
| `city` | 城市（案例涉及地） |
| `content_attr` | 内容属性：避坑 / 揭秘 / 劝退 / 干货 / 故事 / 薪资 |
| `hook_type` | 钩子类型：提问式 / 反差式 / 悬念式 / 痛点式 |
| `audience` | 目标受众 |

### D. 内容结构拆解（核心）
- `structure_outline`：用"段落｜原文梗/要点｜功能"三段式表格还原分镜/段落逻辑。
- 这是本库最有价值的字段，需还原"为什么这样排"。

### E. 爆点 / 传播逻辑
- `why_viral`：爽点 / 信息差 / 情绪共鸣 / 记忆点梗 等，说明它为什么传播。

### F. 可复用套路（核心资产，喂模块⑤）
- `reusable_patterns`：抽象出的通用结构公式、方法论词典、可迁移话术。
- 建议每条案例至少沉淀 1 条可进"脚本模板库"的套路。

### G. 文案与表达特征
- `style_notes`：口语化、反问密度、节奏、人称、梗等。

### H. 风险 / 合规点
- `risk_notes`：匿名化、主观解读标注、地域/公司表述边界、版权与学习用途声明。

### I. 检索辅助
| 字段 | 说明 |
|------|------|
| `tags` | 两级标签：模板类型 + 行业 + 手法（如 `JD阅读理解`, `运营`, `避坑`, `薪酬公式`） |
| `summary` | 一句话摘要，供 AI 快速召回 |
| `related_kb` | 关联模块① JD 的 `jd_id` / 模块⑥ 规则 `rule_id` |

## 二、`template_type` 受控词表（建议持续扩充）
| 类型 | 说明 | 代表案例 |
|------|------|---------|
| `JD阅读理解/避坑拆解型` | 把官方招聘话术翻成潜台词；含**避坑吐槽**（CASE-001/002/003）与**正向种草**（CASE-005）两种语气变体 | CASE-001、CASE-002、CASE-003、CASE-005 |
| `JD判断方法论型` | 不拆单条JD，而是教一套通用判断方法（如"3个问题法"），再用案例实操；是模块⑥价值判断规则库的方法论种子 | CASE-004 |
| `真实体验/vlog型` | 从业者一天/真实状态记录 |
| `薪资揭秘型` | 行业薪资带宽、结构拆解 |
| `入行指南/干货型` | 怎么入行、要什么能力 |
| `人物故事/劝退型` | 个体叙事带出职业真相 |
| `高价值岗位拆解型` | 正面介绍+分析岗位/公司，讲清为何高价值/稀缺，常含行业洞察 | CASE-007、CASE-008、CASE-009 |

## 三、推荐数据来源
1. **小红书 / 抖音 / B站** 职业类博主（搜"这份工作能去吗""面试避坑""XX岗真实"）。
2. **行业社群 / 朋友圈转发** 的爆款视频（你这类分享链接是主来源）。
3. **平台热榜 / 创作中心** 的职场话题榜。
4. **竞品账号** 高赞视频的结构拆解。

> ⚠️ 来源获取限制：小红书/抖音详情页需登录态且有反爬，AI 与脚本**无法自动抓取正文**。实操路径：你提供**口播稿/字幕/截图**，我建标准条目；或你只给链接，我先建骨架（`data_quality: C`）待补。

## 四、数据整理规范
1. **单条一文件**：`cases/CASE-XXX_岗位名.md`，文件名含编号与岗位。
2. **字段命名稳定**：frontmatter 字段一旦定下尽量不变，避免重建索引。
3. **数据表现诚实**：未提供点赞等数据时一律标 `待补` 或 `null`，禁止编造数字。
4. **匿名与合规（红线）**：
   - 仅作**内部学习/结构研究**，注明原作者与出处；不搬运原文、不二创发布、不商用。
   - **匿名化**具体公司名与老板；地域/公司性质判断须基于公开信息，表述为"据报道/集中地"，避免绝对化与地域歧视。
   - 反推潜台词属**主观解读**，正文须标注"个人观点，供参考"。
   - 案例若含**品牌软广/商单植入**（如突兀的具体产品参数），须在 `risk_notes` 明确标注；智能体生成内容**不得在无披露情况下复刻商品植入**。
5. **萃取而非抄录**：重点填 `structure_outline / why_viral / reusable_patterns`，让智能体学到"结构"而非"文案"。
6. **双向关联**：案例涉及某 JD 时，在 `related_kb` 填对应 `jd_id`，并在该 JD 的 `related_kb` 回填 `case_id`。
7. **质量分级**：`A`=含口播稿（最佳）/ `B`=仅标题或截图 / `C`=骨架待补。
