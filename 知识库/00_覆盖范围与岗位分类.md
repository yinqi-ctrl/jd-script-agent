# 知识库覆盖范围与岗位分类（Canonical Scope）

> 本文件定义《这份工作能去吗？》内容策划智能体的**唯一权威覆盖口径**。
> 所有模块（JD库 / 真实体验库 / 案例库 / 脚本库 / 规则库）的条目，必须在 frontmatter 标注 `coverage_status`（in_scope / out_of_scope）与 `scope_category`。智能体检索时**仅召回 in_scope 条目**；out_of_scope 条目仅供留档，不参与选题与脚本生成。

## 一、智能体主要分析的岗位类型（in_scope）

### 1. 内容与运营类
- 新媒体运营
- 内容运营
- 用户运营
- 社群运营

### 2. 产品与商业类
- 产品经理
- 市场营销
- 品牌营销
- 商业分析
- 项目经理

### 3. 出海与跨境类
- 跨境电商运营
- 海外运营
- TikTok运营
- 独立站运营
- 外贸业务

### 4. 增长与数据类
- 投放运营
- 增长运营
- 数据运营
- SEO运营

### 5. 企业通用岗位
- HR
- 销售
- 咨询顾问
- 供应链运营

## 二、暂不覆盖（out_of_scope）
- 医生
- 律师
- 公务员
- 强专业资质职业（如医师/律师/教师/会计持证等需执业资格的）
- 需要长期专业培养的职业（如程序员/算法等需系统工科培养，医师/教师等长周期培养）

> 说明：本智能体定位为"泛商科/运营/商业类岗位"的内容策划，**不覆盖强技术或强资质职业**。即便历史上曾录入程序员、券商研究员、医师、公务员等条目，也统一标记为 out_of_scope，不参与生成。

## 三、检索与生成规则（给智能体）
1. 拿到一条 JD / 岗位名 → 先按 `scope_role` / `tags` 在本库检索 `coverage_status: in_scope` 的 JD 与真实体验。
2. 命中：引用对应真实体验，强化"官方要求 vs 真实体感"反差。
3. 未命中 in_scope 条目：**触发联网检索**，补全该岗位的真实工作状态，并回填真实体验库（标记为 `coverage_status: in_scope`）。
4. 若岗位属于 out_of_scope 类别（如医生/公务员/程序员）：智能体应**礼貌拒做**或提示"该职业不在本栏目覆盖范围内"，不强行生成。
5. 跨方向选题（如 新媒体运营 vs 品牌营销）仅在 in_scope 内部做对比。

## 四、范围外条目的处理原则
- 历史录入的 out_of_scope 条目**保留但打标**，不做物理删除（可恢复、可作对照）。
- 如需彻底清理，由用户显式确认后再执行删除。
- 索引文件中 out_of_scope 条目单独成区，便于核查与清理。
