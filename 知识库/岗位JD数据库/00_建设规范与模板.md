# 岗位 JD 数据库 · 建设规范与模板（V1）

> 所属智能体：《这份工作能去吗？——职业探索类短视频内容策划智能体》
> 模块定位：6 大核心知识库之「1. 岗位 JD 数据库」
> 建设目的：帮助智能体理解招聘市场、岗位要求和企业需求，向下游「选题发现 → JD 分析 → 职业研究 → 内容策划 → 脚本生成」持续供料。

---

## 一、知识库需要包含的信息字段

字段按「检索溯源 / 门槛判断 / 职责日常 / 待遇环境 / 内容增强 / 检索辅助」六组划分。
其中 **E 组（内容策划增强字段）是本模块区别于普通 JD 爬虫的关键**——它是为"这份工作能去吗？"这档节目专门设计的。

### A. 标识与来源（检索 + 溯源）
| 字段 | 说明 | 示例 |
|---|---|---|
| `jd_id` | 唯一编号，建议 `行业缩写-序号` | `IT-001` |
| `title` | 岗位标准名称 | 产品经理 |
| `aliases` | 别名/同义词，用于匹配 | 产品助理 / PM / 产品专员 |
| `function` | 职能大类 | 产品 / 技术 / 运营 / 市场 / 职能 |
| `industry` | 所属行业 | 互联网 / 金融 / 制造业 |
| `company` | 企业名称（可脱敏为"某头部电商"） | 某头部电商平台 |
| `company_type` | 企业性质 | 民营 / 国企 / 外企 / 创业公司 |
| `company_size` | 企业规模 | 10000人以上 / 100-499人 |
| `city` | 工作城市 | 杭州 |
| `collect_date` | 采集日期（强时效，必填） | 2026-08-15 |
| `source` | 数据来源平台 | BOSS直聘 |
| `source_url` | 来源链接（便于复核） | https://... |

### B. 门槛要求（"能不能去"的判断依据）
| 字段 | 说明 |
|---|---|
| `education` | 学历要求（统一口径：大专/本科/硕士/博士） |
| `major` | 专业要求 |
| `experience` | 工作经验年限 |
| `hard_skills` | 硬技能列表 |
| `soft_skills` | 软技能列表 |
| `certificates` | 证书要求 |
| `language` | 语言要求 |
| `entry_barrier` | 入行门槛（高/中/低，AI 推断值） |

### C. 职责与日常
| 字段 | 说明 |
|---|---|
| `responsibilities` | 核心职责要点（列表） |
| `daily_tasks` | 典型日常工作（列表） |
| `reports_to` | 汇报对象 |
| `team_size` | 所属团队规模 |

### D. 待遇与环境（内容钩子核心来源）
| 字段 | 说明 |
|---|---|
| `salary` | 薪资范围（统一"K/月"或"元/月"） |
| `salary_structure` | 薪资结构（底薪+绩效+年终+期权） |
| `benefits` | 福利待遇列表 |
| `work_hours` | 工作时间 |
| `overtime` | 加班强度（高/中/低/无） |
| `remote` | 是否远程/混合办公 |

### E. 内容策划增强字段（本模块专属，专为智能体设计）
| 字段 | 说明 | 为什么重要 |
|---|---|---|
| `selling_points` | 岗位亮点/卖点 | 视频"正向钩子" |
| `pain_points` | 岗位痛点/劝退点 | 视频"反向钩子"，**节目核心** |
| `suitable_for` | 适合人群 | 帮观众对号入座 |
| `not_suitable_for` | 不适合人群 | 强化"能去吗"判断 |
| `career_path` | 职业发展路径 | 长期价值叙事 |
| `controversy` | 常见争议点 | 如 35岁危机/外包/996，天然选题 |
| `content_angles` | 推荐选题角度（3-5 个） | 直接喂给选题策划 |
| `related_kb` | 关联其他库的 ID | 联动职业体验库/趋势库 |

### F. 检索辅助
| 字段 | 说明 |
|---|---|
| `tags` | 标签（行业/岗位/特征混排） |
| `summary` | 一句话 AI 可读摘要 |
| `quality` | 质量等级（A/B/C，见第三节） |

## 二、推荐数据来源

### 1. 综合招聘平台（主力）
- **BOSS直聘 / 智联招聘 / 前程无忧(51job) / 猎聘**：覆盖全行业全层级，适合做广度抽样。
- 用法：按"行业 × 城市 × 经验"维度抽样，每类岗位至少采集 5-10 条 JD 取众数，避免个例偏差。

### 2. 垂直/新兴平台（补深度）
- **牛客网**：校招、技术岗、大厂真题，适合"高门槛/高争议"岗位。
- **拉勾**：互联网垂直，岗位描述质量高。
- **实习僧**：实习岗，用于"入行起点"内容。
- **领英(LinkedIn)**：外企、海外岗、英文 JD。

### 3. 企业官方渠道（补权威）
- 企业招聘官网、校招官网、招聘公众号。适合做"名企标杆岗"样本。

### 4. 行业报告与薪资报告（补趋势）
- 脉脉《年度人才迁徙/薪酬报告》、BOSS直聘《就业趋势报告》、各咨询机构（麦肯锡/BCG/灼识）行业报告。
- 用于校准 `salary`、`entry_barrier`、`controversy` 等推断字段。

### 5. 内容侧补充（补真实语境）
- 同类博主整理合集、知乎/小红书求职帖中的 JD 截图（需人工转写）。
- 用于发现"招聘写一套、实际另一套"的落差——这正是节目卖点。

### ⚠️ 合规与伦理红线
- 仅采集**公开招聘信息**，不抓取求职者简历/姓名/电话等个人隐私。
- 遵守目标平台 `robots.txt` 与用户协议；大规模采集优先用官方开放 API 或授权数据。
- 企业名可脱敏（"某头部电商"），避免商誉风险。
- 每条必带 `source` + `collect_date`，保证可溯源、可时效管理。

## 三、数据整理规范

### 1. 目录与命名
```
知识库/
  岗位JD数据库/
    _INDEX.md                 # 总索引（见第四节）
    互联网/
      IT-001_产品经理.md
      IT-002_后端工程师.md
    金融/
      FIN-001_投行分析师.md
    制造/
      MFG-001_工艺工程师.md
```
- 单条 JD 一文件，文件名 `编号_岗位名.md`，便于 RAG 按文件切片检索。
- 同名异公司岗位：用 `company` 字段区分，文件名加后缀（`IT-001_产品经理_电商.md`）。

### 2. 取值口径统一（AI 一致性关键）
- 学历：仅用 `大专 / 本科 / 硕士 / 博士 / 不限`。
- 城市：用标准城市名，不写"江浙沪""一线城市"等模糊词。
- 薪资：统一 `X-YK·N薪` 或 `元/月`，区间写法一致。
- 加班/门槛：仅用 `高 / 中 / 低 / 无 / 不限`。
- 日期：ISO `YYYY-MM-DD`。

### 3. 去隐私化
- 删除 recruiter 姓名、手机号、微信、邮箱。
- 求职者评论/私信一律不入库。

### 4. 时效管理
- JD 强时效，建议 **6–12 个月**复核更新；`collect_date` 超 12 个月自动标 `quality=C` 待复核。
- 重大政策/行业变动（如教培双减、AI 冲击）触发即时重采。

### 5. 去重规则
- 同企业 + 同 `title` + 同 `city` 视为重复，保留质量高者。
- 不同企业同岗位可并存（用于横向对比"同岗不同命"）。

### 6. 标签体系（建议主从两级）
- 一级：行业（互联网/金融/制造/医疗/教育…）
- 二级：特征（高薪 / 加班 / 稳定 / 风口 / 35岁危机 / 外包 / 考公替代…）
- 标签是 AI 检索的"快捷入口"，建议每条 3-6 个。

### 7. 质量分级
- **A**：官方/名企来源 + 字段完整 + 含 E 组增强字段。
- **B**：来源可靠 + 字段基本完整。
- **C**：片段/二手来源，或超时效待复核。

### 8. AI 友好编码建议
- 关键字段用 **YAML frontmatter**（机器易解析），叙述用 Markdown 正文（人易读）。
- 列表字段用 `-` 无序列表，避免把多个值塞进一个逗号字符串。
- `summary` 写成"一句话能直接被智能体引用"的成句中文。
- 不把大段非结构化文本塞进 `responsibilities` 等应结构化的字段。

## 四、适合 AI 检索的 Markdown 模板

### 单条 JD 模板（直接复制填空）
```markdown
---
jd_id: IT-001
title: 产品经理
aliases: [产品助理, PM, 产品专员]
function: 产品
industry: 互联网/电商
company: 某头部电商平台
company_type: 民营
company_size: 10000人以上
city: 杭州
collect_date: 2026-08-15
source: BOSS直聘
source_url: https://example.com/job/xxx
education: 本科及以上
major: 计算机/商科优先
experience: 3-5年
hard_skills: [需求分析, 原型设计, 数据分析, Axure, Figma]
soft_skills: [沟通协调, 逻辑思维, 抗压]
certificates: []
language: 普通话
entry_barrier: 中
salary: 25-40K·14薪
salary_structure: 底薪+绩效+年终奖+股票期权
benefits: [六险一金, 餐补, 免费班车, 健身福利]
work_hours: 10:00-19:00（弹性）
overtime: 高
remote: 否
selling_points: [薪资高, 平台大资源多, 成长快]
pain_points: [加班严重, 需求反复改, 背锅风险, 35岁危机]
suitable_for: [逻辑强, 爱琢磨用户, 计算机/商科背景, 抗压好]
not_suitable_for: [追求work-life balance, 社恐, 讨厌扯皮]
career_path: 产品助理 → 产品经理 → 高级/资深产品经理 → 产品总监 / 创业
controversy: [35岁危机, 加班文化, 外包与正式工差异]
content_angles:
  - "25K的产品经理，到底每天在干嘛？"
  - "产品经理是不是最容易背锅的岗位？"
  - "35岁还没当总监的产品经理，后来去哪了？"
  - "计算机背景做产品，比商科有优势吗？"
related_kb: [EXP-IT-001, TREND-IT-003]
tags: [互联网, 产品经理, 高薪, 加班, 35岁危机, 风口]
summary: 互联网大厂产品经理，本科起、3-5年经验，月薪25-40K但加班高强度，35岁危机明显，适合抗压强、爱琢磨用户的人，劝退追求稳定的社恐。
quality: A
---

## 摘要
（与 frontmatter 的 summary 一致或略展开，供人快速浏览）

## 核心职责
- 负责XX业务线需求调研与产品规划
- 输出原型与PRD，推动研发落地
- 通过数据复盘迭代功能

## 典型日常工作
- 晨会同步进度，白天对接研发/设计/运营
- 写文档、画原型、看数据报表
- 晚上常加班赶版本

## 岗位亮点
- 薪资处于行业中上
- 大平台能接触海量用户与资源

## 岗位痛点 / 劝退点
- 需求方多、改动频繁，易背锅
- 加班文化普遍
- 35岁后若未晋升管理层压力陡增

## 推荐选题角度
1. 高薪背后的真实一天
2. 最易背锅岗位真相
3. 35岁危机路径推演
4. 背景对比：计算机 vs 商科

## 关联知识库
- 职业体验库：EXP-IT-001
- 行业趋势库：TREND-IT-003
```

## 下一步建议
1. 先用本模板录入 **3-5 条标杆岗位**（建议覆盖"高薪争议型/稳定型/风口型"各一），跑通下游工作流。
2. 同步启动「职业真实体验数据库」建设，与 JD 库的 `related_kb` 做双向关联。
3. 模板字段可按实际采集情况迭代，但 **frontmatter 字段名一旦定下尽量不变**，否则需重建索引。
